Предложи начальный план разработки, какие первые задачи стоит завести?

---

● Предлагаю вести разработку по сквозным срезам: каждая задача даёт работающую функцию от базы до страницы. Порядок такой, чтобы как можно раньше получить минимальный рабочий обмен.

  Этап 0 — основа

  1. Окружение разработки. docker-compose с Postgres; тесты на базе через #[sqlx::test]; единый тип AppError, который превращается в HTTP-ответ.
  2. Каркас интерфейса. Общий layout страницы на wingy-hypertext, раздача статики (стили и скрипты Web Awesome, htmx), навигация, страницы ошибок.
  3. Аутентификация. Регистрация и вход, сессии в Postgres (cookie), extractor CurrentParticipant для обработчиков.
  
  Этап 1 — минимальный рабочий обмен 
  
  4. Круги. Создание, список, страница круга. Решение о вступлении по правилам (open / approval) вынести в core как чистую функцию с unit-тестами.
  5. Управление членством. Заявки, одобрение и отказ, роли, исключение, выход из круга.
  6. Объявления. Создание в выбранных кругах и просмотр. Права проверять по ограничениям 1–2 из docs/domain.md.
  7. Отклики. Смена статусов в core с тестами всех переходов; синхронизация со статусом объявления (reserved → closed).
  
  После задачи 7 сервис уже можно отдать первым пользователям. 
  
  Этап 2 — удобство
  
  8. Лента по всем кругам участника, фильтры, полнотекстовый поиск в Postgres.
  9. Сообщения внутри отклика.
  10. Уведомления в приложении.
  11. Приглашения (invite): ссылка-приглашение в круг.
  
  Что решить до старта (лучше отдельными задачами)
  
  - Способ входа: e-mail и пароль (argon2) или вход по ссылке из письма. Для второго варианта нужна отправка писем уже на этапе 0.
  - Кто действует от имени организации. Сейчас организация — просто участник. Скорее всего, нужна связь «человек → представитель организации»; она повлияет на задачу 3.
  - Категории: фиксированный справочник или свободный текст.
  - Срок жизни объявлений: автоматически архивировать по expires_at или нет. 
  
  Могу завести задачи файлами в issues/ в вашем формате (ГГ-ММ-ДД название.md): либо все, либо только этапы 0–1.
