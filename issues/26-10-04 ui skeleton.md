# Каркас интерфейса

Этап 0. Зависимости: 03.

## Сделать

- Общий layout страницы на wingy-hypertext (`layouts::page`): шапка, навигация, основная область.
- Раздача статики (`tower-http` `ServeDir`): WASM для Wingy components, htmx, стили из `wingy-hypertext/webassets` (`freemax-client`).
- Частичный рендер для htmx-запросов (`HX-Request` → только фрагмент).
- Страницы ошибок 404/403/500 в общем layout.

## Готово, когда

- `/` рендерится в layout со стилями Wingy, переход по навигации работает через htmx без полной перезагрузки.

## Пояснение

Понадобится новый член воркспейса `freemax-client`, его структура будет подобна `../../wikihub/wikihub/crates/client`, автоматизацию сборки также можно подсмотреть в `../../wikihub/wikihub/Makefile.toml`.

## Результат

- `crates/client` (`freemax-client`): WASM на `wingy-hypertext-web` (page, drawer, действия), `webassets/` — `main.js`, `main.css`, htmx 2.0.8.
- `Makefile.toml`: задачи `client`, `build-client`, `copy-static`, `deploy-client`, `optimize-client` по образцу Wikihub. Стили копируются из версии wingy-hypertext, зафиксированной в `Cargo.lock` (задача `copy-wingy-style` на duckscript, работает и под Windows).
- `crates/server/src/view`: `View`, middleware `render_layout` (полная страница / фрагмент для htmx с навигацией `hx-swap-oob`), layout на `Page`/`PageBody`/`PageMenu`, страницы-заглушки `/`, `/circles`, `/about`, страница ошибки.
- `AppError` рендерится в общем layout; fallback — 404; htmx подставляет ответы 4xx/5xx.
- Переключатель цветовой схемы в шапке — компонент `ColorSchemeSelector` из wingy-hypertext (`view/color_scheme.rs` передаёт подписи, поведение — `wingy_hypertext_web::component::color_scheme_selector`); сохранённая тёмная схема применяется inline-скриптом до первой отрисовки.
- Статика по `/webassets` из `http.webassets_dir` (по умолчанию `target/web`).
- Тесты: `crates/server/tests/layout.rs` (полная страница, фрагмент, восстановление истории, 404), unit-тест активного пункта навигации.
- Проверено в headless Chromium: WASM инициализируется, переход по навигации без перезагрузки (обновляются URL, заголовок, активный пункт), страница 404 через htmx, мобильное меню в drawer, «Назад».
- В `main.css` обход двух проблем `Page` из wingy-hypertext: у `main` нет `grid-area`; контейнерный запрос задаёт `--menu-width` самому контейнеру `.page`, где он не действует, — на узком экране колонки меню и aside не схлопывались.

● Да, переделал copy-wingy-style на @duckscript. Под Linux проверил: cargo make -p debug client собирает статику, и target/web/style совпадает со стилями из checkout'а wingy-hypertext. Под Windows не запускал,
  но shell-команд и jq в задаче больше нет.
  
  Как теперь работает задача:
  - запускает cargo metadata через exec;
  - разбирает JSON встроенным json_parse и находит manifest_path пакета wingy-hypertext; на выводе около 1.4 МБ это занимает примерно 0.3 с;
  - через dirname поднимается от crates/lib/Cargo.toml к корню репозитория;
  - копирует webassets/style командой duckscript cp.
  
  Пути обрабатываются средствами Rust внутри cargo-make, поэтому обратные слэши Windows не мешают. Если пакет не найден, задача падает с сообщением wingy-hypertext is not found in cargo metadata.
  
  jq больше не нужен, я убрал его из требований в README.md. Заодно поправил упоминания задачи check-wasm-bindgen, которую вы удалили: в README.md и в «Результате» задачи 04 ещё было написано, что версия
  wasm-bindgen проверяется при сборке.
